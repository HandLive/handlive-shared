# UI string catalog

`ui-strings.json` is the single source of every user-facing string of HandLive on Android, macOS and iOS/iPadOS: labels, buttons, menus, notifications, notification channel names, permission purpose strings, accessibility labels and error messages (decision C20, `../docs/detailed-design/00-common-specs.md` 0.12). English (`en`) is the default, source and fallback language; Vietnamese (`vi`) is the second language. Code never contains display text: each platform generates its resources from this file.

| File | Contents |
|------|----------|
| `ui-strings.json` | The catalog: `version`, `source_language` (`en`), `languages` (`en`, `vi`), `strings` |
| `ui-strings.schema.json` | JSON Schema 2020-12 of the catalog |
| `../tools/strings/check_strings.py` | The checker of 0.12.5 (see below) |

## Entry

```json
{
  "key": "pairing.paired_with",
  "en": "Paired with {device_name}",
  "vi": "Đã ghép nối với {device_name}",
  "comment": "Feedback on both devices when pairing succeeds (HUD, sheet); {device_name} is the peer",
  "platforms": ["android", "macos", "ios"],
  "args": [{"name": "device_name", "type": "string"}],
  "specs": ["PAIR-01"]
}
```

| Field | Rule |
|-------|------|
| `key` | Lowercase `[a-z0-9_]`, 2–5 segments joined by dots. The first segment is the group: `common`, `setup`, `settings`, `pairing`, `status`, `menu`, `clipboard`, `sms`, `call`, `call_audio`, `camera`, `permission`, `notification`, `push`, `error`, `a11y`, `infoplist`. A key never changes when the wording changes; a new meaning gets a new key. Keys stay unique after `.` becomes `_` (Android resource names). |
| `en`, `vi` | A string, or a CLDR plural object: `en` has `one` and `other`, `vi` has only `other`. Every language of `languages` is present and non-empty. |
| `args` | Placeholders `{name}` with `type` `string`, `int` or `double`. Every translation uses exactly the same set, in any order (generators turn them into positional arguments). Dates, times, numbers, sizes and durations are formatted by the system before they are passed in, so they are `string`. |
| `comment` | Required: where the string appears and any length limit — context for translators. |
| `platforms` | Subset of `android`, `macos`, `ios`: the generators of these platforms include the string. |
| `specs` | Leaf function IDs (`CLIP-01`) or sections of `00-common-specs` (`0.11`) that specify the string; they must exist as headings in `../docs/detailed-design`. |
| `plist_key` | Group `infoplist` only, and required there: the Info.plist key (purpose string). |

Conventions of this repository on top of 0.12.1:

- Entries are sorted by key (plain code-point order, as Python `sorted()` gives), so additions from several branches merge cleanly.
- A plural is selected by an `int` argument named `count`.
- Quotes inside a text are typographic: “…” (both languages).
- A text the specs do not spell out yet says so in its `comment` ("Proposed text"); it must go into the specs before release.

## Writing

Follow the design system, section "Writing" (`../docs/design-system/1-foundations/09-viet-noi-dung.md`), and its English part:

- English: title-style capitalization for buttons, menu items, window and sheet titles, tabs, settings row labels, alert and notification titles ("Send Clipboard to Phone", "Pair With {device_name}?"); sentence-style for descriptions, footnotes, alert messages, notification bodies, status text and tooltips ("Connected via Wi-Fi"). Short, active, present tense; no "please", "sorry", exclamation marks or emoji.
- Vietnamese: sentence case everywhere; Apple-style tone marks (hóa, xóa, hủy, tùy, thủy, khỏe — never hoá, xoá, huỷ, tuỳ); terminology "bảng nhớ tạm", "kết nối qua Internet", "Mã an toàn".
- Both: the ellipsis character "…", never three dots; proper names untranslated (HandLive, Wi-Fi, Bluetooth, USB, SIM, Mac, iPhone, iPad, Android); system settings named exactly as each OS shows them in that language ("System Settings › Privacy & Security" / "Cài đặt hệ thống › Quyền riêng tư & Bảo mật", Android "Accessibility" / "Hỗ trợ tiếp cận").
- User content (SMS text, device and contact names) is never translated; it only fills placeholders.

## How the platforms use it (0.12.2)

| Platform | Output | Mapping |
|----------|--------|---------|
| Android | `values/strings.xml` (en, default) and `values-vi/strings.xml`, generated by a Gradle task in `buildSrc` into the build directory | resource name = key with `.` → `_`; plurals → `<plurals>`; `{name}` → `%1$s` / `%1$d` in `args` order; escape `'`, `"`, `@` and `?` at the start and line breaks; a literal `%` becomes `%%` |
| Apple | `Localizable.xcstrings`, `InfoPlist.xcstrings` (source language en) and Swift accessors, generated by a script in `apple/` and committed | keys keep their dots; plurals → String Catalog plural variations; `{name}` → `%1$@` / `%1$lld`; `infoplist.*` → `InfoPlist.xcstrings` under `plist_key` |

APNs pushes carry only a `push.*` key as `aps.alert.loc-key`; the iPhone shows it in its own language (CONN-04). Error codes of the protocol map to `error.*` texts; the `message` of an error is English diagnostics for logs (0.12.4).

## Adding or changing a string

1. Change the specs first, in the hub: the English text in `X.md`, the Vietnamese text in `X.vi.md` (same commit).
2. Change `ui-strings.json` in its own commit in this repository and run the checker. When several agents or people edit this repository at once, take the workspace lock around the commit: `mkdir ../.locks/shared` (fails while someone else holds it), commit, then `rmdir ../.locks/shared`.
3. Change the code, which reads the generated resources only.

## Checking

Run from this repository's root with the tools venv (`python3 -m venv tools/.venv && tools/.venv/bin/python -m pip install -r tools/strings/requirements.txt`):

```sh
tools/.venv/bin/python tools/strings/check_strings.py              # rules of 0.12.5; prints OK, exit 1 on errors
tools/.venv/bin/python tools/strings/check_strings.py --docs       # also warn about texts the specs do not quote
tools/.venv/bin/python tools/strings/check_strings.py --self-test  # tests of the checker itself
```

Errors: schema; unique keys (also after `.` → `_`) in sorted order; every language present; identical placeholder sets and no stray brace; CLDR plural categories with an `int` argument `count`; no empty text, no leading or trailing whitespace, NFC, no control character, "…" instead of "..."; Apple-style tone marks in `vi`; `plist_key` exactly in group `infoplist`; `specs` IDs that exist in `../docs/detailed-design` (override with `HANDLIVE_DOCS_DIR` or `--docs DIR`). Warning: translations that end with different punctuation.

`--docs` looks for each `vi` text in the Vietnamese specs and each `en` text in the English specs, under `docs/detailed-design` and `docs/design-system`: `X.md` is English when an `X.vi.md` twin exists; a lone `X.md` counts in the language it is written in (the docs are being translated). Placeholders match the example or the `<name>` the spec writes in their place, and a final period is optional. Missing texts are warnings only. CI (`ci-shared`) runs the self-test and `--docs`; `tools/schemas/check_schemas.py` also checks the catalog excerpt quoted in 0.12.1.
